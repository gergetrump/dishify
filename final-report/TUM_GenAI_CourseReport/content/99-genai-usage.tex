\chapter{Acknowledgment of GenAI Usage}
\label{ch:genai-usage}

Generative AI was used both in building Dishify and in preparing this report.
This chapter states where, and how the output was checked.

\section{In the Product}

Generative models are a runtime component of Dishify itself, as documented
in Section~\ref{sec:pm-prompting} and in
Chapter~\ref{ch:safety-reflection}. Gemini handles voice transcription and
image ingredient detection; a model hosted via OpenRouter produces the
recipe-fit reasoning and the step augmentation. The strongest guarantees apply
to the recipe-fit reasoning, which must pass schema, recipe-identity, and
grounding validation before it is displayed. The other three paths are bounded
differently: voice and image output are parsed against a fixed JSON schema and
then \emph{shown to the user for confirmation} before use, and step
augmentation is schema-checked and constrained by prompt to avoid introducing
ingredients the recipe does not imply. No generated text reaches the user
unchecked, but the checks are not identical across features.

\section{During Development}

The team used AI coding assistants throughout implementation --- for scaffolding
services, drafting tests, writing configuration, and debugging --- alongside
conventional review. % CONFIRM the specific assistants each member used.
Nothing was merged unread: every change went through pull-request review by a
second team member and had to pass the GitHub Actions test suite, which is the
same standard we would apply to hand-written code. The adversarial security
harness described in Chapter~\ref{ch:safety-reflection} was itself written with
AI assistance and then verified case by case against the running service.

\section{In This Report}

This document was drafted with the assistance of a large language model
(Anthropic Claude, used through an agentic coding environment with access to
this repository and the deployed system). The workflow was deliberately
evidence-first rather than generative-first:

\begin{itemize}[itemsep=1pt, topsep=3pt]
    \item \textbf{Facts came from the artefacts, not the model.} Architectural
          claims were read out of the source; the ranking weights, the 72
          restriction tags, the validation limits, and the guardrail behaviour
          were taken from the code that implements them.
    \item \textbf{Figures are primary evidence.} Every screenshot in
          Chapter~\ref{ch:user-guide} was captured from the live deployment
          through a scripted browser session, not mocked up. The latency
          figures in Section~\ref{sec:reflection} and the adversarial results
          in Table~\ref{tab:safety-eval} were measured against that same
          deployment while writing this report.
    \item \textbf{User data was not generated.} The acceptance-testing numbers
          are the team's own survey results. Where per-participant detail was
          not available, the report says so rather than inventing it.
    \item \textbf{The team reviewed and edited the result.} The argument,
          judgements, and the critical conclusions --- notably that the project
          did not pass on retention --- are the team's own, and every section
          was read and revised before submission.
\end{itemize}

\noindent
The draft was additionally submitted to a second, independent model acting as a
strict reviewer against the grading criteria, and the resulting corrections
were incorporated. We regard this as the appropriate use of the technology for
an assessed document: fast to draft, but held to the same evidentiary standard
as any other engineering artefact.
